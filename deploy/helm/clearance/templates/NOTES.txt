CLEARANCE är utrullad som release "{{ .Release.Name }}" i namespace "{{ .Release.Namespace }}".

Appen nås via:
{{- if .Values.ingress.enabled }}
  https://{{ .Values.ingress.host }}
{{- else }}
  (ingen ingress aktiverad - portforwarda frontend-tjänsten för att nå den)
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "clearance.fullname" . }}-frontend 8080:{{ .Values.frontend.port }}
{{- end }}

Kontrollera läget:
  kubectl -n {{ .Release.Namespace }} get pods,cronjobs
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "clearance.fullname" . }}-api

Migrationsjobbet kördes som en Helm-hook FÖRE den här utrullningen. Se dess logg:
  kubectl -n {{ .Release.Namespace }} logs job/{{ include "clearance.fullname" . }}-migrate-{{ .Release.Revision }}

VIKTIGT innan första riktiga inloggning fungerar:
  - Migrationsjobbet skapar app_user/app_worker som NOLOGIN (db/bootstrap.sql).
    Egenhostat måste LOGIN-roller för API:t och arbetaren finnas, med lösenord
    som matchar database-url / worker-database-url i hemligheten. Se
    docs/selfhosted-kubernetes.md, avsnittet om roller.
{{- if not .Values.secret.existingSecret }}
  - Du kör utan existingSecret: hemligheten skapades ur values (test/bootstrap).
    Sätt secret.existingSecret i drift och håll värdena utanför git.
{{- end }}
